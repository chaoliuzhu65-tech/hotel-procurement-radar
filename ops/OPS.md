## 1. 一句话与边界

**做什么**：OpenClaw + 飞书生态下的酒店采购核价助手——自然语言/图片/报价单 → 多源查价 → 卡片汇报 →（可选）写入飞书多维表格。

**不做什么**：
- 自动下单、旺旺聊天（仅 **本地 MCP 版**；Web 版无）
- 市场外拓 / 竞品雷达类能力（非本仓）
- 推送密钥、token、客户敏感价到公开文档

| 能力 | Web 版 | 本地 MCP 版 |
|------|--------|-------------|
| 查价 / 以图搜图 / 导出 Base | ✅ | ✅ |
| 自动下单 / 旺旺 | ❌ | ✅ |
| 安装需求 | 无（对已接入飞书机器人说话即可） | 需本机 MCP + Skill |

**新人目标路径**：安装 Skill → 说一次触发词核价 → 知道结果落在卡片和/或哪张 Base 表。

## 2. 安装 / 升级

### 2.1 部署到 OpenClaw Agent skills/

```bash
# 目标目录以各 Agent 实际 skills 根为准，常见为：
cd ~/.openclaw/workspace/skills

# 首次安装（公开仓）
git clone https://github.com/chaoliuzhu65-tech/hotel-procurement-radar.git

# 已有目录则升级（拉取 main，不推送）
cd hotel-procurement-radar
git fetch origin
git checkout main
git pull --ff-only origin main
```

**验收**：目录内至少存在 `SKILL.md`、`USER-GUIDE.md`、`README.md`。重启或热加载 Agent skills 后，触发词应能唤醒本 Skill。

> 注：部分旧文档仍写 `delonix-ai/hotel-procurement-radar`；**以公开仓** `chaoliuzhu65-tech/hotel-procurement-radar` 为准。

### 2.2 仅复用 schema（不装完整 Skill）

若 Agent 已能查价，只需写表：按 §5 字段名在飞书 Base 建表，用各租户已有的 Base 写入能力（如 `lark-cli base +record-*`）追加行。token / app_secret 只放本地配置，**不要**写进公开仓。

### 2.3 配置占位（本地，勿入库）

```yaml
# 示例本地配置片段（占位符）
bitable_token: "<FEISHU_BITABLE_APP_TOKEN>"   # 多维表格 app_token

# app_id / app_secret / user_access_token → 仅本地密钥库，禁止提交
```

## 4. 数据源路由与容灾链

### 4.1 数据流

```text
用户自然语言 / 图片 / 报价单
    → OpenClaw 云端引擎
    → Web 搜索多源（农产品≈9 + 电商≈4 + 工程≈3 + 酒店用品≈3 ≈ 19）
    → 智能路由 + 容灾 fallback
    → 飞书交互卡片 +（可选）多维表格写入
```

### 4.2 容灾链（主源失败自动切换）

| 主源 | Fallback |
|------|----------|
| 农业农村部 | 新发地 → 商务预报 |
| 新发地 | 农业农村部 → 惠农网 |
| 惠农网 | 一亩田 → 新发地 |
| 一亩田 | 惠农网 → 新发地 |
| 商务预报 | 农业农村部 |
| 寿光蔬菜指数 | 农业农村部 → 新发地 |
| 猪价网 | 农业农村部 |
| 淘宝/天猫 | 京东 → 拼多多 |
| 京东 | 淘宝 → 拼多多 |
| 拼多多 | 淘宝 → 京东 |
| 1688 | 淘宝 → 京东 |
| 我的钢铁网 | 1688建材 → 造价通 |
| 造价通 | 我的钢铁网 |
| 淘宝酒店用品 | 1688酒店 → 京东企业购 |

运维只关心：**卡片里「数据来源」字段是否标明实际命中源**；主源挂了仍有价 → 容灾正常。

### 4.3 频率与响应（公开说明级）

- 单品约 10–30s；3–5 品 30–60s；>10 品建议分批（1–3 分钟）
- 同账号约每分钟 ≤10 次查询（防抖/限流，具体以运行时为准）

## 6. 多维表格容错（ensure_bitable 逻辑）

Skill 设计意图（见 `SKILL.md`）：

1. **无 token** → 自动建表「酒店采购比价记录」，回写 `bitable_token`
2. **有 token 无权限** → 提示用户授权，不静默失败
3. **表不存在** → 自动重建

### 已知文档不一致（重要）

| 文档 | 表述 |
|------|------|
| `SKILL.md` v4 | 多维表格「自动创建 / 自动容错」 |
| `USER-GUIDE.md` v2 | 「结果导出 → 飞书多维表格」标为 🔜 开发中 |
| 实测（学习笔记 2026-10-13） | 共享池采购比价表**已有样例行** |

**运维准则：以实测为准**——在目标 Base 查是否新增记录；不要只信某一份 md。若 Web 版当前环境未真正写表，卡片结果仍可用，写表可改用手动导出或 `lark-cli` 补写。

## 8. 故障排查

| 现象 | 可能原因 | 处理 |
|------|----------|------|
| 无反应 / 不弹引导 | Skill 未加载或路径错 | 确认 `skills/hotel-procurement-radar/SKILL.md` 存在；重载 Agent |
| 查无价 / 全源失败 | 上游 Web 源不可达或搜索配额 | 换品名重试；看日志是否走完 fallback；错峰再查 |
| 有卡片无写表 | 未配 token；或 USER-GUIDE「开发中」与运行时一致 | 查本地 `bitable_token`；按 §5 建表；**以 Base 是否新增行为准** |
| **无 token** | 首次未建表 | 允许 Skill 自动建表，或手建后填占位配置 |
| **无权限** | Bot/用户缺 Base 读写 scope | 开放平台补 `base:*` 相关权限并发布；或让有权限用户授权；CLI 场景可 `--as user` 补齐 |
| **表不存在** | 表被删或 table_id 错 | 重建表并对齐 §5 字段；更新 `table_id` |
| 价格与实采差大 | 地域/运费/规格差异（正常） | 以本地批发价为准；看风险提示是否含运费说明 |
| 触发了下单相关 | 误用本地 MCP 能力 | Web 版应无下单；确认未接本地下单 MCP |

密钥类问题：**只在本地轮换**，不把新 token 写进本 ops 目录或公开 PR。

## 9. 已知限制

1. **写表文档不一致**：USER-GUIDE 🔜 vs SKILL 自动容错 → **以实测为准**（§6）。
2. **自动下单仅本地 MCP**，Web 版不做采购下单。
3. 电商/部分农产品源在不同 README 副本状态标记可能不同（✅/⏳/🔜）——以运行时能返回为准，不必为「状态 emoji」单独开运维单。
4. 农产品价地域性强；输出仅供核价参考，不构成采购承诺。
5. 历史价格走势、异常预警等为后续功能，不在本 ops v0.1 保障范围。
6. 本手册**不覆盖** `delong-ai-radar` 等市场雷达仓。
